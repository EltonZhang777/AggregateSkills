# ADR 0002: Compress Docs cross-platform replacement outcome

Accepted: the workflow accepts user-selected files across Agent Skills hosts without probing OS, filesystem, or storage provider. For each file, retain a verified original backup, stage the candidate beside the source, and use the host's replace operation. A successful return is success; skip post-replace readback. If replacement reports an error, report the source state as unknown, retain and report the backup, and do not roll back. The workflow makes no universal filesystem transaction or restoration guarantee, and files in a batch remain independent: one failure does not undo another file's successful replacement.

## Revision (2026-10-12)

This revision supersedes the decision above to perform unconditional replacement on ordinary paths. Candidates may be applied only through a storage backend that supports version-conditional writes: in one atomic commit, the backend must verify the version token of the validated snapshot; on mismatch it must leave the destination unchanged, and on success it must retain the target's original access boundary. A backend that cannot establish these properties must return `not_applied` before creating a backup or staging file or modifying the destination. Ordinary local paths and the current `apply_candidate.py` do not provide this guarantee; the current version refuses all local-path application while still allowing candidate generation. A future backend must define a verifiable and safely retryable backup strategy; if the commit outcome is uncertain, keep the verified backup and return `replacement_unknown`, without readback or rollback.
